# 论证层 · 逻辑说明书（Argument Layer）

> 提案是说服，说明书是诚实。两者必须一起交付。
> 用途：让客户看懂「为什么这么判断」，让你自己能在被追问时完整辩护。

## 什么时候写

- 完整项目交付：必附完整版逻辑说明书
- 单次判断超过一页：附压缩版（论点树 + 最弱一环 + 反证）
- 面试/演示前的作品：必写——被追问时按说明书防守

## 完整版结构

### 1. 论点树

一句话一个节点，从前提推到结论：

```
前提（事实/数据）
  → 推断（从这里读出了什么）
    → 判断（据此选了什么方向）
      → 承诺（这个方向如果不成立，会先在哪里露馅）
```

每一层都能回答「上一层的依据是什么」。

### 2. 关键决策点

列出整条链上真正做过选择的地方（通常 3-5 个），每个写：当时有哪些选项、为什么选这个、放弃了什么。

### 3. 最弱一环

整条链最容易被打断的一环。写清楚：

- 它依赖什么证据（或假设）
- 如果要推翻它，需要什么数据
- 它被推翻后，结论是局部调整还是整体重来

### 4. 反证清单

「如果这条判断是错的，我该去搜什么/看什么数据来验证」——2-3 条具体的反证动作，不是泛泛的「再做一轮调研」。

### 5. 换假设测试

把 1-2 个关键假设替换成相反假设，结论会怎么变。写出变化，不逃避。

### 6. 证据账本

只标关键结论（不是全部）：每条的最强依据、最弱依据、以及「这条是数据还是判断」。

### 7. 边界声明

这份交付不覆盖什么；哪些数字是占位；哪些问题需要客户提供数据才能回答。

## 压缩版（单次判断用）

- 论点树（3 层以内）
- 最弱一环（一句话 + 推翻它需要什么）
- 反证动作（1 条）

## 质量门槛

写不出「最弱一环」或「换假设测试」的结论 → 判断还没做完，先不交付。

## 辩护模式（被追问时）

顺序固定：最弱一环 → 反证 → 换假设。

先主动说出最弱的地方（建立诚实信用），再给反证动作（展示可纠错），最后换假设（展示推理弹性）。不要在追问下死守论点树的第一层——先跳到自己最没底的地方。
