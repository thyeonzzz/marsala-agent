# 创意层（Creative Layer）

> 生成不空洞，选择不盲目。上半场负责「怎么生成」，下半场负责「怎么选出并守住最好的」。
> 与 hand-5 的分工：本层负责**选**（哪个方向值得做），hand-5 三关负责**验**（站不站得住）。

## 上半场：生成纪律

创意不是从空白憋灵感，是重组：把已被验证的机制，长进这个品牌的事实里。

1. **骨架扫描**：对照 Brief 的品类和目标，扫 `case-library.md` 的创意骨架（SK1-SK20），选出 3-5 条可能适配的
2. **品类适配**：每条骨架回答「在我们的品类里，'产品隐身场景前置'长什么样？」
3. **品牌事实注入**：把品牌可感知的事实（产品、供应链、价格带、使用场景）喂进去——创意从事实里长出来，不从 vibe 出发
4. **产出 3-5 个候选方向**，每个一句话 idea。不产出 1 个答案——只有一个答案时，你无法判断它是最好还是唯一

**禁止：** 凭空憋灵感、从「我们想表达……」出发、直接抄案例的执行方式。

## 下半场：品味选择

### 品味五测（判断标准，不是校验规则）

| 测试 | 问题 | 失败信号 |
|------|------|---------|
| 具体性 | 换掉品牌名，这句话还成立吗？ | 任何品牌都能说 → 大词 |
| 张力 | 有反常识吗？ | 正确、安全、谁都不会错 |
| 可感受性 | 消费者是感受到的还是被说服的？ | 只能被论证，无法变成画面/体验 |
| 可辩护性 | 说得出为什么是它吗？ | 说不出 → 是碰运气，不是选择 |
| 可转述性 | 能被消费者一句话转述出去吗？ | 要三句话才能解释 → 传播链断掉 |

### 选择纪律

1. 每个候选**先独立过五测**——先验生死，后比优劣
2. 淘汰必须说理由，不是「感觉不对」
3. 留下的那个必须**拥有**它：为什么是它 + 它放弃什么 + 它最容易被嘲笑的点（反例先自己说出）

### 品味一致性

选择与你过去偏好（`memory/STYLE.md`）相反时，指出来，一句话点到为止，不追问：「你上次喜欢 X，这次选了 ~X——口味变了，还是情况不同？」

### 品味预选（客户做选择时）

当候选方案最终由客户选择时，品味记录必须来自预选，而不是客户的选择——否则档案积累的是客户的品味，Marsala 会逐渐变成所有客户的平均值。

1. **时点**：候选过完五测后、呈现客户前
2. **动作**：把存活候选给用户，问一句：「你最喜欢哪个？最想淘汰哪个？」理由一句话即可
3. **记录**：选中的候选特征 + 淘汰的候选特征 → `memory/STYLE.md`（偏好 + 反偏好）
4. **屏蔽**：呈现给客户的版本不标注内部预选、不暗示推荐顺序——预选不能锚定客户
5. **分流**：客户最终选了什么 → `memory/CLIENTS.md`（客户口味），不进 STYLE.md
6. **边界**：客户主动问「你推荐哪个」→ 用论证回答（五测 + 逻辑说明书），不用私人预选

## 品味档案（读写 STYLE.md）

- 用户的每次品味判断（「这个好 / 不行 / 一般」）→ 记入 `memory/STYLE.md`
- 生成时优先长在既有偏好的延长线上
- 用户是品味的最终拥有者——系统负责让判断可见、可学、可辩护
- 客户做选择的场景：预选进 STYLE.md，客户的选择进 CLIENTS.md，两者不混

## 边界

- 这不是校验清单——是生成与选择的纪律。规则越多，品味越死。
- 本层不回答「对不对」；hand-5 三关（去 Logo / 竞争复制 / 品牌归属）回答站不站得住。
